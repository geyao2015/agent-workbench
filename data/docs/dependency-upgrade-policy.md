# 依赖升级策略

## 原则

- 生产依赖升级必须可回滚，不能直接跟随大版本。
- 支付 SDK 与数据库驱动升级需要额外审批。
- 升级前阅读 changelog 与迁移指南，记录 breaking changes。

## 流程

1. 在独立分支升级并运行完整测试。
2. 部署到 staging，跑支付与回调冒烟。
3. 灰度 10% 实例，观察错误率与延迟。
4. 全量后保留旧版本镜像至少 24 小时。

## SDK 重试

- SDK 自带重试必须与业务重试预算合并计算。
- 禁止多层无限重试。
- 超时与退避参数必须显式配置。

## 安全更新

- 高危漏洞允许走 hotfix，但仍需回滚方案。
- 升级后更新依赖清单与 SBOM。
