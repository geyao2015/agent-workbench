# 测试策略

## 测试金字塔

- 单元测试：状态机、幂等键、错误码映射等纯逻辑。
- 契约测试：API 请求响应与回调格式，防止上下游字段漂移。
- 集成测试：数据库、消息队列与 outbox relay 的真实交互。
- 端到端测试：创建订单到支付回调的核心链路，仅在 staging 运行。

## 发布门禁

- 单元与契约测试必须全绿。
- 集成测试覆盖 migration 与回滚脚本。
- 核心链路 E2E 在 staging 通过后才能进入灰度。
- 覆盖率不设硬指标，但支付与幂等逻辑必须有分支覆盖。

## 故障回归

- 每个线上事故至少补一条回归测试。
- INC-042 的回归用例：并发重复回调只产生一条支付尝试记录，且第二个回调返回 `duplicate: true`。
- 测试数据使用合成数据，不引用真实订单或用户信息。

## 性能测试

- 回调处理目标：P95 低于 800ms，峰值 200 QPS。
- 压测必须包含重复回调与网关超时场景。
- 压测结果记录在 release notes 中，作为灰度决策依据。
