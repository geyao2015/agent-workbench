# 发版 Runbook

适用于 checkout-service 的标准版本发布。紧急修复走 hotfix 流程，不适用本清单。

## 角色

- Release captain：协调窗口、执行检查、决定是否继续。
- On-call engineer：观察指标、处理告警。
- Approver：对不可逆步骤（数据库迁移、回滚）做人工审批。

## 标准流程

1. 冻结代码：确认目标分支没有未合并的发布阻塞项。
2. 生成 release notes：从提交记录提取变更，标注风险等级。
3. 在 staging 完整执行一次发布与冒烟。
4. 检查变更窗口与依赖服务，避免与支付网关发布重叠。
5. 执行数据库迁移，确认只做向后兼容的加列或建索引。
6. 按 10% → 50% → 100% 灰度，每档观察至少 10 分钟。
7. 打开 feature flag 前必须经过单独审批。
8. 发布完成后更新状态页与值班记录。

## 冒烟检查

- `GET /healthz` 返回 200。
- 创建订单、支付确认、回调处理三条核心链路通过。
- 支付成功率与回调延迟在阈值内。
- 最近 10 分钟没有新增 5xx 峰值。

## 回滚

- 代码回滚：切回上一个稳定镜像，保留事件日志用于审计。
- 数据回滚：只允许反向迁移，禁止直接删除生产数据。
- feature flag 回滚：优先关闭开关，不重新发版。
- 回滚后 30 分钟内禁止再次发布同一版本。

## 审计记录

每次发版必须记录：版本号、变更范围、审批人、迁移 ID、灰度时间点、回滚决策与原因。记录写入 release 审计表，不可修改。
