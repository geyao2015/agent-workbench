# Feature Flag 指南

## 命名

- 使用 `service.feature` 形式，例如 `checkout.confirm_v2`。
- 每个 flag 必须有 owner、默认值、创建原因与清理日期。

## 发布

- 新功能默认关闭，先发布代码再打开 flag。
- 按租户或流量比例灰度，禁止一次全量。
- 打开 flag 需要人工审批并记录审计。

## 回滚

- 优先关闭 flag，不重新发版。
- 关闭后观察至少 10 分钟再决定下一步。
- flag 关闭不代表数据回滚；数据修复需要单独迁移。

## 清理

- 功能稳定后删除 flag 与死代码。
- 逾期未清理的 flag 会在发布检查中被标记为阻塞项。
