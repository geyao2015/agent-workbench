## 2. 建议顺序

1. Mock 数据真实化：所有 Demo、截图与 E2E 的地基。
2. 多模态 S1 → S2 → S3：图片上传/识别可独立验证，语音最后做。
3. 对话分支 + 服务端队列：补齐会话模型和并发语义。
4. 上下文预算、摘要、重试/超时：Agent 深度的核心，需要真实模型量化。
5. 模型 Span、token/成本、答案评测：形成可观测与质量闭环。
6. 持久化恢复、工具沙箱/threat model：从“能跑”到“敢用”。
7. CI、部署与展示材料：让招聘方能点开、能复现。

## 3. 每个切片的交付格式

- 问题：难在哪里，普通实现为什么会坏。
- 方案：关键决策与替代方案。
- 证据：测试、指标、代码位置、可运行入口。
- 追问：面试官可能继续问的 2–3 个问题。

## 4. 维护规则

- 完成一个能力层切片后更新“现状/下一步”，待办状态同步到 [plan.md](plan.md)。
- 不把功能清单写进本文件；只写难点、缺口和证据。
- 新增层或改变顺序前先确认，不顺手扩大范围。
